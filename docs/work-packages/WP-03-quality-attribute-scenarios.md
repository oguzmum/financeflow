## Goal

Make QA-1 … QA-11 concrete and testable, then rank them. This ranking drives every later trade-off.

## Definition of done

- [ ] ≥ 1 six-part scenario (source, stimulus, environment, artifact, response, response measure) for each of QA-1, 2, 3, 4, 7, 9
- [ ] A small _utility tree_ ranking the attributes by importance × difficulty
- [ ] Top 3 attributes named explicitly in `requirements.md` §4

## Learning goals & concepts

- Quality attribute scenarios (SEI)
- Utility tree / ATAM-lite
- Why "the system must be fast" is not a requirement
